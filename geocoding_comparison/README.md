# Сравнительный анализ систем геокодирования: Яндекс.Геокодер, DaData, GigaChat

## 1. Описание значимости артефакта

### Процесс и контекст использования
- **В рамках какого процесса / сценария используется артефакт**  
  Процесс выбора технологического компонента для геокодирования (преобразование адресов в координаты и обратно) при интеграции картографических сервисов в информационную систему.
- **На каком этапе он применяется**  
  На этапе технического проектирования (или предпроектного анализа) перед принятием решения о закупке/использовании конкретного API.

### Цель создания
 
  Сравнить три кандидата (Яндекс.Геокодер, DaData, GigaChat) по точности прямого и обратного геокодирования, скорости ответа и наличию встроенных метрик качества, чтобы обоснованно выбрать один сервис для внедрения.

### Что становится определено
- **Какие решения зафиксированы (данные, логика, контракты и т.д.)**  
  - Метрики точности каждого сервиса (процент адресов с номером дома, процент адресов до улицы).  
  - Сравнительная таблица качества и времени ответа.  
  - Вывод о непригодности GigaChat для геокодирования.  
  - Рекомендация: использовать DaData как универсальный сервис или Яндекс при приоритете точности прямого геокодирования.

### Пользователи артефакта
  - Системные аналитики (для уточнения требований к геокодеру).  
  - Разработчики (для выбора API и интеграции).  
  - Руководитель проекта (для принятия решения о лицензировании).

### Использование в дальнейшем
- **Какие действия становятся возможны после его создания**  
  - Обоснованный выбор поставщика геокодера.  
  - Написание технического задания на интеграцию.  
  - Планирование бюджета (если сервис платный).  
  - Разработка прототипа с выбранным API.
- **В каких следующих шагах он участвует**  
  В архитектурном решении, в спецификации интеграции, в приёмочных испытаниях.

### Последствия отсутствия 
  - Риск выбрать неподходящий сервис (например, GigaChat) и получить на продакшене неверные координаты или медленные ответы.  
  - Дополнительное время на эксперименты с каждым API после начала разработки.  
  - Невозможность аргументировать выбор перед заказчиком или руководством.  
  - Возможное увеличение затрат на доработки и исправления.

## 2. Методология сравнения

- **Выборка**: 100 уникальных адресов для прямого геокодирования и 100 различных координат для обратного геокодирования.
- **Критерии оценки**:
  - Прямое геокодирование: точность определения координат вплоть до номера дома или хотя бы до улицы.
  - Обратное геокодирование: получение адреса не менее чем до улицы.
  - Время ответа (среднее значение).
- **Источники данных**: Запросы выполнялись вручную через Postman с последующей фиксацией ответов. Для DaData и Яндекса использовались встроенные метрики точности (`qc_geo` и `precision`), для GigaChat классификация выполнена экспертно.
- **Обработка**: Excel для подсчёта процентов и группировки.

## 3. Результаты сравнения

### 3.1 Прямое геокодирование (адрес → координаты)

| Сервис | Точность "номер дома" | Точность "улица и выше" | Примечание |
|--------|----------------------|------------------------|-------------|
| **Яндекс.Геокодер** | **97%** (14 `number` + 83 `extract`) | 98% (+1 `street`) | `near` (2%) – неточный адрес |
| **DaData** | **82%** (`qc_geo=0`) | 96% (+14 `qc_geo=1`) | 4% `qc_geo=2` (только город) |
| **GigaChat** | ≈0% | ≈0% | Координаты систематически расходятся на километры |

### 3.2 Обратное геокодирование (координаты → адрес)

| Сервис | Адрес до улицы (включительно) | Примечание |
|--------|-------------------------------|-------------|
| **DaData** | **76%** (71 `extract` + 5 `street`) | 19% `other`, 5% пустой список |
| **Яндекс.Геокодер** | **64%** (21 `extract` + 43 `street`) | 36% `other` |
| **GigaChat** | **18%** (только город/область) | 81% неверно, 1% без ответа |

### 3.3 Время ответа (среднее)

| Сервис | Среднее время | Оценка |
|--------|---------------|--------|
| DaData | ~1 секунда | стабильно |
| Яндекс | ~1 секунда | стабильно |
| GigaChat | ~2 секунды | медленнее, менее стабилен |

## 4. Вывод и рекомендация по выбору

- **DaData** – оптимальный выбор для универсального использования (сильное обратное геокодирование 76%, прямое геокодирование на уровне 96% для улиц и 82% для домов).
- **Яндекс.Геокодер** – рекомендуется, если критична максимальная точность прямого геокодирования (97% адресов с номером дома). Обратное геокодирование (64%) можно компенсировать вспомогательным сервисом.
- **GigaChat** – непригоден для задач геокодирования в практических проектах из-за низкой точности, отсутствия встроенных метрик и более высокого времени отклика.

**Итоговая рекомендация**:  
Внедрить **DaData** как основной сервис для задач прямого и обратного геокодирования. При необходимости повышения точности прямого геокодирования до 97% использовать **Яндекс.Геокодер** (возможно, как второй уровень). GigaChat исключить.

## 5. Исследование API-контрактов

В ходе работы были изучены официальные документации и выполнены тестовые запросы через Postman к следующим endpoint'ам:
- Яндекс.Геокодер: `/v1/geocoder` (прямой и обратный)
- DaData: `/api/v1/clean/address` (прямой) и `/api/v1/geolocate/address` (обратный)
- GigaChat: `/api/v1/chat/completions` с промптами для геокодирования

Все запросы зафиксированы, ответы сохранены и использованы для расчёта метрик.
